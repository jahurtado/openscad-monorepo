# Design rules

The **conventions you must follow** when designing parametric models in OpenSCAD.

They apply to **any** design, whether it is driven by specifications or measurements (`openscad-design-from-specs`) or from a 3D STL mesh (`openscad-design-from-stl`).

The **`design-conventions-reviewer`** subagent takes them into account to ensure a design complies.

- **DO NOT** model a part as a sequence of 2D extrusions. Infer features and reconstruct with primitives whenever possible.
- **DO NOT** embed polygons in the scad file unless they are **trivial: few vertices and ALL straight segments**. Approximating a **curved/organic** contour with a straight-segment `polygon()` is **NOT** "trivial, no arcs" — it is a **FACETED TRACE** and is **forbidden**: that profile goes as a smoothed DXF (next rule). **Faceted trace** is the name this repo gives the anti-pattern of **sampling a curve into a list of points and pasting them into the code** instead of reconstructing the shape; it is the most common way a model *looks* right and *is* built wrong, which is why it gets a name that the design skills and the `design-conventions-reviewer` refer to it by. *(A/B benchmark gotcha: a curved arm/web was embedded as a straight-edged `polygon()` instead of a smoothed DXF.)*
- **CREATE an external DXF** in the same directory as the scad module when you need a linear or radial extrusion because the part is geometrically complex to build with basic primitives, **or when the profile has curves/arcs/organic edges** (even if it looks "simple"): the criterion is NOT how many vertices it has, but **whether the contour is curved** → if it is, DXF. (To extract the silhouette of an existing geometry or STL as a DXF: `slice.py --project <axis> --dxf` — see the [tools guide](tools-guide.md#slicepy). If the silhouette exists **physically** — a cutout, a template, the broken part — the validated path is to **photograph it on a known-pitch grid background and trace it**: see the `openscad-design-from-specs` skill (`.claude/skills/openscad-design-from-specs/SKILL.md`), which carries the conditions for a faithful tracing.)
- **APPLY conversion/smoothing to external DXFs** with the `dxf_smoother` tool to smooth arcs and convert them to an OpenSCAD-compatible format.
- **Reuse libraries** in `lib/` whenever possible instead of reinventing designs.
- **DO NOT** run CSG operations on coplanar faces: every negative/cutter must **protrude** past each face it crosses (never flush), because `difference()` removes only what it intersects. **CHECK** that the correction is made in the right direction, otherwise residual walls will appear (capping holes or cavities). For a **through-hole, verify it stays open on BOTH faces**: an overhang applied at only one end leaves the hole **capped at the other** (an interior void that's closed at the surface). *(A/B benchmark gotcha: holes that showed an interior cavity but were closed on one face; they passed `check.py` and `compare.py` all the same.)*
- **DO NOT model ZigZag shapes** that mimic screw threads. Instead model with a simple drill (cylinder) and cut the thread with a dedicated thread library — this template does not bundle one.
- **Review the use of rounded-edge cubes**: reach for the rounded-box primitive in `lib/` in preference to `hull()` (much cheaper to render). What is available, and with what signature, lives in the headers of the `lib/` files.
- For complex parts, evaluate whether you can model by **sculpting** a basic primitive using extruded profiles in orthogonal planes. For example, you can have one profile (DXF) in the XY plane (extruded in Z) and one or more profiles in other planes (XZ and/or YZ) and apply `difference` or `intersection` operations.
- When using external components, **review the ORIENTATION** in case a translate/rotate needs to be applied to it.
- **The print bed is 180 × 180 mm.** Every single-print part keeps its **footprint ≤ 180×180**; if it doesn't fit, split it into pieces, reorient it or print it diagonally. Check it with the `bbox` that `check.py` reports for each `*_print` — not from memory. *(If you adapt this repo to another printer, this is the number to change.)*
- **DECLARE constants** for every important dimension that the user might modify.
- **TAG every constant that carries a position** with its provenance: `// MEASURED: <what+value>` (verified with calipers on the real part) or `// ADJUST: <what>` (an estimate, to be confirmed). When the real measurement arrives, **flip the tag `ADJUST → MEASURED` in place and NEVER delete the trail** (the record of how it was fixed). There is no global maturity state: tracking is **per-constant**.
- **`assert()` goes INSIDE a module, never at the top level of a file that gets `use`d.** OpenSCAD **does not execute the top-level statements of a file imported with `use`** — so an `assert()` in the header of `modules/<piece>.scad` is skipped **silently** exactly when it matters: when `main.scad` renders the piece. Put the invariants in a module (`<pfx>_asserts()`) and **call it from the geometry module**; verify it fires by deliberately breaking one.
- **DO NOT break the compatibility of anything reusable** (a `lib/` primitive or a component): changing its signature, origin or semantics shifts features **silently** in all its consumers. Locate the consumers (`grep -rn "<name>"`) and either preserve the old behavior (shim) or rewrite the consumers **in the same commit**; validate that no render breaks (`check.py --all-projects`).
- **Include a "clearance" parameter** when a part has to mate with another, so the manufacturing tolerance can be adjusted.
- **A numeric PASS does NOT imply a usable part.** `check.py` (watertight/genus/bbox), `compare.py` (contour/holes/volume) and `render3d --vs` (heatmap) measure **surface/volume/topology** and **cannot distinguish** what determines function: which **side** of a hole is capped, which **face** a pocket is on, **conical vs flat** (countersink), **blind vs through**, **hexagonal vs round**, or the **Ø/position** of an embedded cavity. **Close out every functional feature with section inspection** —`slice_viewer --vs <mesh>` (overlay of the model against the reference, plane by plane; see the [guide](tools-guide.md#slice_viewerpy))— before calling a part good. *(Recurring lesson from the A/B benchmark: the surface metric oversells; the section cut is the real arbiter.)*
- **The escape hatch is `// LINT-OK: <reason>`.** When one of these rules genuinely does not apply to a piece of geometry, mark that line with `// LINT-OK: <reason>` **stating why**. It is not a mute switch: the `design-conventions-reviewer` **judges the reason** and fails the review if it reads as an excuse rather than a real exception. Use it sparingly — and never to wave through a faceted trace or a flush cutter over a coplanar face, which are exactly the two it is most tempting to silence.
